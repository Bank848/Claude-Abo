Портативный слепок настроек Claude Code одного конкретного человека — глобальные инструкции, инженерные правила, **45 отобранных навыков (skills)** (7 написаны самим автором — 3 с нуля, 4 — самописные обёртки над сторонними инструментами — 1 адаптирован на основе исходного навыка, остальные заимствованы из внешних репозиториев, для каждого навыка указано происхождение в `sources.json`), реальные примеры памяти, манифест происхождения навыков и кросс-проектное хранилище знаний — всё упаковано так, чтобы новый экземпляр Claude Code (или человек, который его настраивает) мог на новой машине воспроизвести те же рабочие привычки и возможности. Это **шаблон для адаптации, а не конфиг для запуска "как есть"**: персональные идентификаторы вычищены и заменены плейсхолдерами, а некоторые разделы имеют смысл только если вы также внедрите описанные в них инструменты.

## Быстрый старт

**Короткий путь:** склонируйте репозиторий, откройте его в Claude Code и запустите `/adopt` — команда проведёт с вами интервью (какие опциональные части вам нужны, список плагинов, целевые пути) и выполнит за вас шаги 2-6 и 8-9 из списка ниже, отмечая прогресс в возобновляемом журнальном файле. Шаг 7 (установка самих плагинных экосистем) намеренно оставлен за рамками `/adopt` — это придётся сделать самостоятельно. Приведённые ниже ручные шаги — это то, что автоматизирует `/adopt`; они пригодятся и тем, кто предпочитает делать всё руками или хочет проверить, что именно изменится, прежде чем запускать команду.

1. **Склонируйте репозиторий** в любое удобное место на целевой машине.
2. **Решите сейчас насчёт единственной опциональной части** — ответьте да/нет, поскольку это определяет, что вы удалите на шаге 5: локальный ИИ (Ollama) для предварительного сжатия. Подробности — в разделе "Опционально: ___" ниже.
3. **Скопируйте `global-config/CLAUDE.md`, `agents/*.md`, `hooks/block-dangerous-git.py`, `skills/*` и `tools/`** в свой собственный `~/.claude/` (слияние или замена — на ваше усмотрение). Именно эти файлы заставляют работать правила маршрутизации, защитный git-хук, каталог навыков и чекер обновлений — а не просто читаются как проза. **Перед копированием `CLAUDE.md` перепишите раздел "Installed Plugins"так, чтобы он перечислял только то, что установлено у вас** — в оригинальной копии владельца заявлено, что включены конкретные плагины; перенос этого без изменений заставит вашего Claude лгать о доступных инструментах.
4. **Слейте `global-config/settings.example.json`** со своим `~/.claude/settings.json` (после замены `<YOUR_HOME>`; на macOS/Linux также замените лаунчер `py` в команде хука на `python3` — как поставляется, эта запись рассчитана на Windows).
5. **Удалите Ollama, если на шаге 2 вы ответили "нет".** Быстрый способ: абзацы про Ollama в вашей копии CLAUDE.md + `notes/local-ollama-models.md` + `tools/ollama/`.
6. **Замените плейсхолдеры** во всём, что вы оставили — полный список см. в шаге 8 раздела "Как это внедрить" ниже.
7. **Установите упомянутые плагинные экосистемы** (superpowers, ecc и т.д.) — см. "Что ещё придётся установить отдельно" ниже.
8. **По желанию скопируйте `notes/`** в своё собственное хранилище second-brain, а **`memory-examples/`** — в папку авто-памяти Claude Code для соответствующего проекта.
9. **Запустите сессию Claude Code и убедитесь**, что он подхватил новый CLAUDE.md — например, попросите план реализации и проверьте, вызывается ли `/plan-pro`, или спросите про маршрутизацию моделей и посмотрите, вернётся ли лестница стоимости.

Остальная часть README подробно разбирает каждую составляющую.

## Что здесь есть

```

├── ATTRIBUTION.md                         # Credits for the upstream repos the third-party skills were adopted from
├── .claude/commands/adopt.md              # Run `/adopt` in this repo to interview + auto-apply the steps below
├── global-config/
│   ├── CLAUDE.md                          # Global instruction file (~/.claude/CLAUDE.md equivalent)
│   ├── settings.example.json              # Sanitized ~/.claude/settings.json — hooks, plugins, model default
│   ├── agents/                            # 3 pinned-model subagent definitions (opus, haiku-batch, fable-medium)
│   ├── hooks/block-dangerous-git.py       # PreToolUse gate that asks before risky git commands
│   ├── rules/ecc-common/                  # 10 engineering-discipline rule files (ecc plugin ecosystem)
│   ├── skills/                            # 45 curated skill folders (the actual SKILL.md instructions, not just an index — see sources.json for provenance)
│   ├── SKILLS_INDEX.md                    # Personal index of installed skills/plugins + when to use which
│   ├── memory-examples/                   # 7 real auto-memory entries showing the memory system's format/patterns
│   ├── templates/                         # 2 starter templates to copy into a new repo (project-CLAUDE.md, conventions.md)
│   └── tools/
│       ├── skill-update-check/
│       │   ├── check.ps1                  # Weekly update checker — reads sources.json from this same folder
│       │   └── sources.json               # Real provenance manifest: 45 personal skills + 3 pip + 2 npm + 1 binary tool
│       └── ollama/ollama-digest.ps1       # On-demand local-model pre-digest helper (see the Ollama section below)
└── notes/                                 # 3 notes: a personal cross-project "second brain" vault (example content)
```

### `global-config/CLAUDE.md`
Сердце всей настройки. В нём закодированы:

- **Маршрутизация моделей с учётом стоимости** — основной цикл работает на Sonnet как оркестраторе, делегируя задачи субагентам Haiku/Opus/Fable в зависимости от сложности, с жёсткими правилами о том, кто читает сырые файлы, а кто — уже готовые выводы.
- **Вынос тяжёлых задач наружу** — крупные задания запускаются в отдельных сессиях вместо того, чтобы раздувать (и наращивать счёт) текущей.
- **Рабочий процесс планирования** — `/plan-pro` как планировщик по умолчанию.
- **Соглашение о хранилище second-brain** — одно правило ("привязано ли это к конкретному репозиторию?"), решающее, что живёт в хранилище, а что — в docs/ADR репозитория.
- **Защитный git-хук** — гейт PreToolUse, который спрашивает подтверждение перед деструктивными git-командами.
- **Особенности шеллов** — правила по хередокам для Bash tool против PowerShell tool (боль, специфичная для Windows, познанная на собственном опыте).
- **Самомониторинг контекста** — когда Claude должен сам проактивно предлагать `/compact`.
- **Правила против ИИ-штампов в тексте** — полный тайско-английский свод правил, чтобы черновой текст читался как написанный человеком (лексика, которой стоит избегать, структурные паттерны, соответствие регистру); самая крупная и наиболее переиспользуемая часть файла. Подробности лежат в `memory-examples/`.
- **PR по умолчанию как черновик**, **обязательное подтверждение перед планированием cron/облачных агентов**, **лаконичное озвучивание хода долгих команд**, **особенность общей группы вкладок claude-in-chrome** для параллельных сессий и **проактивная проверка Supabase RLS** для любого проекта, использующего Supabase.

### `global-config/rules/ecc-common/`
Общая инженерная дисциплина из плагинной экосистемы ecc (everything-claude-code): рабочий процесс TDD, неизменяемость (immutability), формат коммитов, чек-лист безопасности, уровни серьёзности в код-ревью, делегирование агентам. Полезно только если вы также используете ecc (см. "Что ещё придётся установить" ниже).

### `global-config/skills/`
45 отобранных папок `SKILL.md` (плюс вспомогательные скрипты/справочные/файлы данных там, где они есть) — они охватывают писательское и маркетинговое ремесло (copywriting, copy-editing, hallmark, marketing-council, pricing...), инженерные процессы (debug-mantra, poka-yoke, second-brain, dependency-audit, secrets-audit...), дизайн (design-system, ui-ux-pro-max, banner-design, mobbin-references...) и мета-навыки для управления самим Claude Code (skillify, grilling, second-brain, graphify, plan-pro, shipping-a-branch...). `poka-yoke`, `plan-pro` и `shipping-a-branch` написаны автором с нуля; `graphify`, `dembrandt`, `markitdown` и `mobbin-references` — самописные навыки-обёртки, чей SKILL.md оригинален, а базовые инструменты сторонние (указаны в `ATTRIBUTION.md` и отслеживаются по версиям в `sources.json`); `deslop-defaults` — адаптированный (заимствован из `ibelick/ui-skills` и переписан безотносительно к стеку); остальные заимствованы из внешних репозиториев — происхождение каждого навыка см. в `sources.json`, а благодарности источникам — в `ATTRIBUTION.md`. Это по-настоящему переиспользуемые артефакты промпт-инжиниринга, а не просто описания навыков — скопируйте их в `~/.claude/skills/`, и они сразу заработают.

### `global-config/memory-examples/`
7 реальных записей из системы авто-памяти Claude Code владельца (не факты о конкретном проекте, а переносимые привычки "как я работаю"): разграничение соглашений об именовании для кросс-сессионных сообщений, паттерн использования локальной Ollama как предварительного сжатия, правило о том, что на самом деле операционно означает "обновить книжку навыков", особенность экранирования в shell (`\b` незаметно превращается в байт backspace), запись обратной связи о том, насколько агрессивно урезать раздувшийся контекст, а также полный подкрепляющий материал (таблицы лексики + примеры до/после) для правил против ИИ-штампов из CLAUDE.md, на тайском и английском. Эти записи призваны показать *форму* хорошей записи памяти (правило + почему + как применять) не меньше, чем их конкретное содержание — см. `global-config/rules/ecc-common/` о том, как память вписывается в общий рабочий процесс, и раздел "จำ/บัญญัติ" в CLAUDE.md о различии локальной и глобальной памяти, которым пользуется этот владелец.

### `global-config/tools/skill-update-check/sources.json`
Реальный манифест внедрения навыков/инструментов владельца — настоящие данные о происхождении (URL исходных репозиториев, заметки об установке, история версий) для всех 45 личных навыков (включая написанные автором и адаптированные) плюс 3 пакета pip, 2 пакета npm и 1 бинарный инструмент. В паре с `check.ps1` это позволяет тому, кто внедряет `claude-clone-template`, отслеживать апстрим-обновления для навыков, скопированных в `~/.claude/skills/`, точно так же, как это делает исходный владелец. Значения `last_seen_commit` для получателя в основном будут `unknown`/устаревшими, пока он один раз не запустит `check.ps1 -Ack`, чтобы установить собственную точку отсчёта.

### `global-config/templates/`
Два небольших стартовых файла (`project-CLAUDE.md`, `conventions.md`) для копирования в новый репозиторий при первой настройке — "роутер"-CLAUDE.md проекта длиной ≤45 строк и шаблон conventions/green-gate. У каждого есть блок комментариев с заполняемым пресетом PRESET для стека, который вы разворачиваете (сейчас есть только пример для Python-веба); добавьте собственный пресет так же, если вашему стеку нужен свой.

### `notes/`
Примерный контент из хранилища second-brain владельца в Obsidian: инвентарь локальных моделей Ollama, закладки репозиториев и разные справочные заметки. Они показывают, *какого рода вещи* уместны в кросс-проектном хранилище — это не универсальный обязательный набор. Сохраните саму идею структуры, а содержимое со временем замените своим.

## Как это внедрить

1. **Скопируйте `global-config/CLAUDE.md`** в свой собственный `~/.claude/CLAUDE.md`. Слейте с тем, что у вас уже есть, или полностью замените — решать вам. Сначала прочитайте файл; удалите разделы, которые к вам не относятся. **Перепишите раздел "Installed Plugins" прежде, чем делать что-либо ещё с этим файлом** — сейчас в нём утверждается, что установлены и включены конкретные плагины (superpowers, ecc, pordee, lazyweb, andrej-karpathy-skills), и Claude указывается не упоминать их установку. Это верно для исходного владельца, но не для вас. Замените этот раздел своим реальным списком плагинов или удалите его, пока вы что-нибудь не установите.
2. **Скопируйте `global-config/agents/*.md`** в `~/.claude/agents/` и **`global-config/hooks/block-dangerous-git.py`** в `~/.claude/hooks/`. Именно они делают правила маршрутизации моделей и защитный git-гейт из CLAUDE.md реально работающими, а не просто текстом.
3. **Скопируйте `global-config/skills/*`** в `~/.claude/skills/`. Это основная часть реальной ценности — 45 рабочих папок с навыками, а не просто их описания.
4. **Слейте `global-config/settings.example.json`** со своим `~/.claude/settings.json` (сначала замените `<YOUR_HOME>` на реальный путь к домашней папке). Сливайте, а не перезаписывайте, если у вас уже есть settings.json — возьмите запись `hooks.PreToolUse` и всё нужное из `enabledPlugins`. В поставляемом хуке используется Windows-лаунчер `py`; на macOS/Linux сначала замените его на `python3`.
5. **Скопируйте `global-config/rules/ecc-common/`** в `~/.claude/rules/` **только если** вы устанавливаете плагин ecc. Иначе пропустите.
6. **Скопируйте `global-config/memory-examples/*.md`** в папку авто-памяти того проекта, к которому хотите их применить (авто-память Claude Code хранится по проектам, в `~/.claude/projects/<project>/memory/`), либо прочитайте их как справочный материал и напишите свои с нуля.
7. **Скопируйте `notes/`** в своё собственное хранилище second-brain (любую папку, которую видит Obsidian или обычные markdown-инструменты), либо полностью пропустите, если хранилище вам не нужно.
8. **Найдите и замените каждый плейсхолдер** — это самый важный шаг:
   - `<YOUR_USERNAME>`, `<YOUR_HOME>` → ваше реальное имя пользователя Windows/системы и путь к домашней папке
   - `<YOUR_VAULT_PATH>` → место, где вы храните (или планируете хранить) своё хранилище second-brain
9. **Скопируйте `global-config/tools/`** (и `skill-update-check/`, и, если вы оставили Ollama, `ollama/`) в `~/.claude/tools/`, затем **установите собственную точку отсчёта в `sources.json`**: запустите `check.ps1 -Ack` один раз после копирования навыков, чтобы `last_seen_commit` отражал отправную точку, которую контролируете вы, а не историю исходного владельца.

## Что ещё придётся установить отдельно

Этот репозиторий содержит **ссылки на экосистемы навыков и правила для них** — не сами экосистемы. Чтобы инструкции CLAUDE.md имели смысл, вам нужно установить:

Установите их через систему плагинов Claude Code на новой машине, а затем приведите `SKILLS_INDEX.md` в соответствие с тем, что вы реально установили.

## Заметка о тарифном плане подписки и уровне Fable 5.1

Лестница маршрутизации моделей в `CLAUDE.md` венчается субагентом `fable-medium` — намеренно дорогим, редко используемым уровнем эскалации для самых сложных задач. Исходный владелец на тарифе **Max**, где эта модель доступна. Если у вас тариф **Pro** (или любой план без доступа к Fable 5.1), вызов `fable-medium` просто завершится ошибкой.

Прежде чем копировать `CLAUDE.md` как есть, проверьте свой тариф. Если у вас нет Fable 5.1:
- Удалите абзацы про `fable-medium` и пункт "สุดบันได" (вершина лестницы) из раздела маршрутизации моделей.
- Измените потолок лестницы так, чтобы она заканчивалась на `opus` — логика маршрутизации (эскалация на Opus для сложных/высокорисковых задач) по-прежнему работает, просто выше Opus эскалировать будет некуда.
- Не копируйте `global-config/agents/fable-medium.md` в `~/.claude/agents/`.

`/adopt` задаёт этот вопрос в рамках интервью и делает эту правку за вас; если вы копируете файлы вручную, сделайте это сами, чтобы Claude не пытался постоянно вызывать субагента, недоступного на вашем тарифе.

## Опционально: локальный ИИ (Ollama) для предварительного сжатия

Исходная настройка использует локальные модели Ollama как **бесплатный, "лоссовый" уровень предварительного сжатия** — прогоняя длинный низкорисковый текст (логи, многословную документацию) через локальную модель, чтобы сжать его *перед* тем, как он попадёт в контекст платной модели. Он находится **ниже Haiku** в лестнице стоимости и не является уровнем маршрутизации: нет доступа к инструментам, нет контекста репозитория, только текст на входе и текст на выходе. Он экономит деньги, но не добавляет возможностей. Ничто другое в этом репозитории от него не зависит.

**Итак, вопрос, на который вам нужно ответить самостоятельно: хотите ли вы настраивать локальные модели Ollama ради этого?**

### Если нет
Пропустите весь этот раздел. Удалите абзацы про Ollama из своей копии `CLAUDE.md` и уберите `notes/local-ollama-models.md`. Всё остальное прекрасно работает и без этого.

### Если да
1. **Установите Ollama** с [ollama.com](https://ollama.com).
2. **Решите, где будет храниться набор моделей.** Модели большие (модель на 27B — это десятки гигабайт), а расположение по умолчанию — на системном диске (`%USERPROFILE%\.ollama` на Windows). Если на системном диске мало места, перенесите хранилище на диск побольше — в исходной настройке именно поэтому использовался `D:\ollama`. На Windows установите переменную окружения `OLLAMA_MODELS` на выбранный путь перед загрузкой моделей; на других платформах есть эквивалентные подходы через переменные окружения или симлинки.
3. **Загрузите хотя бы одну инструктивную модель общего назначения** (например, `ollama pull qwen2.5:7b-instruct` или похожую инструктивную модель на ~7–9B — достаточно маленькую, чтобы работать быстро, и достаточно хорошую, чтобы суммаризировать). Исходный инвентарь в `notes/local-ollama-models.md` показывает один из возможных вариантов набора: тяжёлая модель на 27B для лучшего качества, модели среднего размера 7–9B для скорости/рассуждений/кода и одна модель с поддержкой зрения (`llava:7b`) — воспринимайте этот список как вдохновение, а не как список покупок.
4. **Освойте паттерн использования:** подать файл на вход, получить сжатый дайджест на выходе —
   ```powershell
   Get-Content <file> | ollama run <model> "<instruction>"
   ```
   (Передавайте файл через пайп; не запихивайте длинные промпты в аргумент.)
5. **Помните одно жёсткое правило:** вывод локальной модели **никогда не является истиной в последней инстанции**. Это лоссовое сжатие для низкорискового текста. Если от содержимого зависит решение — платная модель читает оригинал, всегда.

Это полностью опционально и может быть пропущено. Существует исключительно для того, чтобы сэкономить на токенах при работе с объёмным текстом.

## Совместимость с другими ИИ-инструментами для разработки

Этот шаблон создан специально для **Claude Code**. Механизмы, на которые он опирается — автозагружаемый `CLAUDE.md`, инструмент `Skill`, хуки `settings.json`, определения субагентов — это функции Claude Code, а не переносимый формат файлов. Указать Codex CLI, ChatGPT, Antigravity, Cursor или любой другой инструмент на этот репозиторий не заставит их автоматически "подхватить" навыки или правила; ничто здесь не заработает "из коробки" вне Claude Code.

Что *можно* адаптировать вручную:
- `global-config/CLAUDE.md` — это обычный текст: скопируйте нужные части в `AGENTS.md` (который читают Codex CLI и ещё несколько инструментов) или в кастомный системный промпт. Сначала уберите всё, что ссылается на механизмы, специфичные для Claude Code (spawn_task, инструмент Skill, маршрутизация субагентов) — они нигде больше не будут иметь смысла.
- Каждый навык в `global-config/skills/<name>/SKILL.md` — это просто markdown-файл с инструкциями. Его можно вставить в кастомные инструкции другого инструмента, но вы потеряете автоматический триггер, а любые прилагающиеся скрипты предполагают шелл, который этот инструмент реально может запускать.
- Хуки (`settings.json`) и файлы субагентов (`agents/*.md`) — это только для Claude Code, эквивалента для их переноса не существует.

Если вы ежедневно пользуетесь Codex/ChatGPT/Antigravity, этот репозиторий всё равно полезен как *справочный материал* (правила письма, фиксы для .docx, логика защитного git-хука) — просто рассчитывайте копировать/вставлять нужные части, а не подкладывать папку целиком и ожидать, что она заработает.

## Оговорка: это настройка одного конкретного человека

Этот слепок происходит из конкретного рабочего процесса: тайско-англоязычного пользователя на машине с Windows. Это видно повсюду — в двуязычных разделах CLAUDE.md, в особенностях PowerShell против Bash.

Берите то, что полезно, отбрасывайте то, что нет. Ничто здесь не является предписывающей лучшей практикой — это то, что сработало для одного человека, записанное достаточно хорошо, чтобы быть переносимым. Настоящая ценность — в *форме* системы (маршрутизация по стоимости, вынос тяжёлой работы наружу, один дом для каждого кусочка знания, защитные гейты на деструктивных командах), а не в каком-то отдельном правиле.
