# Close-Out Log — บันทึกปิดงานราย-repo

> **โค้ดบอก "อะไร" · docs/adr บอก "ทำไมทั้งโปรเจกต์" · log ตัวนี้บอก "วันนี้ทำอะไร + ต้องระวังอะไร"**
> เป้าหมายเดียว: session หน้า (คนหรือ Claude ที่ความจำรีเซ็ต) อ่านแล้ว **ไม่ต้องเสีย 2 ชม.ไปสะดุดกับดักเดิม**

พอร์ตมาจาก `docs/log/` ของ repo `leenawatling-bit/link` — ได้ Claude ที่ต่อเนื่องข้าม session ด้วยไฟล์ธรรมดา ไม่ต้องพึ่ง tooling

## กติกาเหล็ก (P0): ต้องเสร็จใน ~2 นาที
พิธีกรรมที่กินเวลาเกินไป dev part-time จะข้าม — และ log ที่เขียนครึ่งเดียว/stale **แย่กว่าไม่มี** (ทำลายความเชื่อถือจนไม่มีใครอ่าน). ดังนั้น: template ตายตัว + **เพดาน ≤25 บรรทัดต่อ session** + distill มือ ห้าม dump ทั้งแชต

## ก่อนเขียน header ต้องเช็คนาฬิกาจริงก่อนเสมอ (ห้ามเดา/ประมาณจาก "ความรู้สึกว่าเวลาผ่านไปเท่าไหร่")
รัน `date` (Bash) หรือ `Get-Date` (PowerShell) **ในเทิร์นนี้จริงๆ** ก่อนพิมพ์ `[HH:MM]` ทุกครั้ง แล้วใช้ผลลัพธ์นั้นตรงๆ — ห้ามพิมพ์เวลาที่ไม่ได้มาจาก output ของคำสั่งจริง เหตุผล: โมเดลประเมิน "เวลาที่ผ่านไปจริง" จากจำนวน turn/tool-call ที่ทำระหว่างทางไม่แม่น (เจอเคสจริง 2026-09-15: เขียน `[02:30]`→`[03:20]`→`[03:35]` ทั้งที่นาฬิกาจริงตอนนั้นคือ ~00:45→01:00→01:42 ตามลำดับ ห่างกันเกือบ 2 ชม.) — เช็ค timezone ด้วยว่าตรงที่ user คาดหวังจริง (`date` เปล่าอาจ report timezone ผิดถ้า shell env ตั้งไว้ต่างจากเครื่อง เช่น MSYS/WSL vs Windows local — เทียบกับ `git log --date=format-local:...` หรือถาม user ถ้าไม่ชัวร์)

## Recite ก่อน append — verbatim ทุกครั้ง
> **Mantra ปิดงาน:**
> 1. **ทำไมชิ้นนี้ก่อน?** — ลำดับ (คนต่อจะได้ไม่รื้อ)
> 2. **เลือกอะไร ทิ้งอะไร เพราะอะไร?** — ทางที่ไม่เลือก โค้ดไม่บอก
> 3. **อะไรจะกัดคนต่อ?** ← 🔑 บรรทัดที่แพงสุด
> 4. **หมกอะไรไว้ไหม?** — ตอบตรง ห้าม over-claim · ไม่มีหนี้ = เขียน "ไม่มี" ห้ามเว้นว่าง

ท่อง ≈5 วิ (ไม่กระทบ P0) → แล้วเขียนลงไฟล์ตาม 4 หัวข้อข้างล่าง

## 4 หัวข้อบังคับ — ตัดข้อไหนไม่ได้ (คู่กับ mantra ข้างบน)

| หัวข้อ | ตอบ | ทำไมต้องมี |
|---|---|---|
| **ทำไมตอนนี้** | ทำไมเลือกทำชิ้นนี้ก่อนชิ้นอื่น | ลำดับสำคัญ — คนต่อจะได้ไม่รื้อลำดับ |
| **ตัดสินใจ** | เลือกอะไรระหว่างทาง + เหตุผล | ทางเลือกที่ทิ้งไป โค้ดไม่บอก |
| **⚠️ ระวัง** | กับดัก/ของเปราะ/สมมติฐานที่ถืออยู่ | 🔑 **บรรทัดที่มีค่าที่สุด — ถ้าเขียนได้ข้อเดียว เขียนข้อนี้** |
| **ยังไม่ทำ** | หนี้/ของค้าง (ไม่มี = เขียน "ไม่มี") | กันลืม + กัน over-claim ว่า "เสร็จ" |

## เส้นแบ่ง — อย่าเขียนซ้ำที่อื่น (P1: หนึ่งเรื่อง หนึ่งที่)
| เนื้อหา | ไปที่ไหน ไม่ใช่ที่นี่ |
|---|---|
| เรื่อง user / ข้ามโปรเจกต์ / glossary / feedback | ระบบ **memory** (`~/.claude/memory` + MEMORY.md) |
| state สำหรับ resume session ต่อ | skill **save-session** ของ ECC |
| การตัดสินใจระดับสถาปัตย์ (อีก 6 เดือนมีคนถาม "ทำไม") | **ADR** (`docs/adr/`, immutable + supersede) |
| สถานะแผน/UI artifact ข้ามโปรเจกต์ ("ไปถึงไหนแล้ว") | **`<YOUR_VAULT_PATH>\worklog\INDEX.md`** — pointer เดียว ไม่ใช่เนื้อหา, ดู `<YOUR_VAULT_PATH>\projects\worklog-index\spec.md` |
| **สิ่งที่คนอ่าน repo นี้ session หน้าต้องรู้เพื่อทำต่อ** | ✅ **ที่นี่** |

## รูปแบบไฟล์
`docs/log/YYYY-MM-DD.md` — ไฟล์เดียวต่อวัน · **append** ใต้ header เวลาของแต่ละงาน · ห้ามแก้ของเก่า

```markdown
# 2026-07-17

## [HH:MM] <ชิ้นงานที่ปิด>
ทำไมตอนนี้: ...
ตัดสินใจ: ... (เพราะ ...)
ระวัง: ...            ← 🔑 กับดักจริงที่จับได้
ยังไม่ทำ: ...         ← หลังถาม "หมกอะไรไว้ไหม" (ไม่มี = "ไม่มี")
```

ถ้ามี finding ค้าง (non-blocker) จาก review/verify → หย่อนต่อท้าย "ยังไม่ทำ" ของ log ล่าสุด (ถังเดียว — ดู workflow `adversarial-verify` · สองถัง = drift)

## เริ่ม session ต้องอ่านก่อน
**อ่าน `docs/log/` ไฟล์ล่าสุดก่อนเริ่มงานเสมอ** — log ที่ถูกอ่านคือ log ที่จะถูกเขียนต่อ (ถ้าไม่มีใครอ่าน มันจะตายเงียบ). เทมเพลต `project-CLAUDE.md` สั่งข้อนี้ไว้แล้ว — **แต่ต้อง verify ว่า CLAUDE.md ของ repo นี้มีประโยคสั่งจริงหรือแค่พูดถึง `docs/log/` เฉยๆ** (เจอเคสจริงที่ <YOUR_VAULT_PATH>: CLAUDE.md มีแค่บรรทัดบอกว่า session-content อยู่ที่ `docs/log/` ไม่มีประโยคสั่ง "อ่านก่อนเริ่มงาน" จริง ต้องเพิ่มเอง) — ถ้าไม่มีให้เสนอเพิ่มให้ user แทนที่จะสันนิษฐานว่ามีอยู่แล้ว

**`docs/log/INDEX.md` เป็นของบังคับทุก repo ตั้งแต่ 2026-09-15** (ก่อนหน้านั้นเป็น optional ตามตัวอย่างที่ <YOUR_VAULT_PATH> — เปลี่ยนแล้วเพราะ repo ใหม่ไม่มีทางรู้ว่าควรสร้างเองถ้าไม่มีกฎบังคับ) — เริ่ม session ให้เปิด `docs/log/INDEX.md` ก่อนเสมอ (ชี้ตรงไปไฟล์ล่าสุด เร็วกว่า `ls` เดา) ถ้ายังไม่มีไฟล์นี้ในโปรเจกต์ (repo เก่าก่อน 2026-09-15 ที่ยังไม่เคยสร้าง) ให้ backfill ทันทีในรอบที่เจอ (ดูขั้นตอนสร้าง/แก้ใน "วิธีใช้ใน session")

## วิธีใช้ใน session
1. เริ่ม session: อ่าน log ล่าสุด (ถ้ามี) → รู้ว่าค้างอะไร ระวังอะไร
2. ปิดงานหนึ่งชิ้น (หรือก่อนจบ session / ก่อน commit ที่จบก้อน): recite mantra → append 4 หัวข้อ
3. เกิน 25 บรรทัด = distill ให้สั้นลง อย่ายืดไฟล์
4. เจอ glossary ใหม่ / บทเรียนข้ามโปรเจกต์ / preference ของ user ระหว่างทาง → เขียน **memory** ทันที (type reference/feedback ตามกติกา global) แล้ว log ใส่แค่ pointer "→ memory" — fact อยู่ memory ที่เดียว (P1)
5. ถ้างานที่กำลังปิดมีแถวเปิดค้างอยู่ใน `<YOUR_VAULT_PATH>\worklog\INDEX.md` (grep ด้วย project slug
   — ทะเบียน slug อยู่บนสุดไฟล์นั้น) → flip สถานะแถวนั้นเป็น `done`/`superseded`/`abandoned`
   ตามจริงก่อนเขียน log ปิดงาน (ดู `<YOUR_VAULT_PATH>\projects\worklog-index\spec.md`)
6. สร้างไฟล์ `docs/log/YYYY-MM-DD.md` ใหม่ (วันแรกของวันนั้น) → **ต้องอัปเดต `docs/log/INDEX.md` คู่กันเสมอ ไม่ใช่ optional อีกต่อไป**:
   - มี `INDEX.md` อยู่แล้ว → เพิ่ม 1 บรรทัดชี้ไปไฟล์ใหม่ (วันที่ + สรุปสั้นว่าเปิดวันนี้ทำอะไร) ไว้บนสุด (ล่าสุดอยู่บนสุด)
   - ยังไม่มี `INDEX.md` เลย (repo เก่า/ยังไม่เคยทำ) → **สร้างใหม่ทันทีในรอบนี้** ไล่ list ไฟล์ทั้งหมดใน `docs/log/*.md` ที่มีอยู่ (เก่าสุดล่างสุด ใหม่สุดบนสุด) ให้ INDEX สมบูรณ์ตั้งแต่ต้น ไม่ใช่แค่ชี้ไฟล์ใหม่ไฟล์เดียวลอยๆ
   - ไม่ทำ = index หลุดตกยุคทันทีวันถัดไป (P1: ที่เดียวชี้ถูกเสมอ)
7. ทุกครั้งที่ append entry ใหม่ลงไฟล์ log ของวันเดิม (ไม่ใช่ไฟล์วันใหม่) **ไม่ต้องแตะ INDEX.md** — INDEX ชี้ระดับ "ไฟล์ต่อวัน" เท่านั้น ไม่ใช่ระดับ entry ย่อยในไฟล์

## จำแค่ 3 ข้อพอ
> **1. 4 หัวข้อ ≤25 บรรทัด — "ระวัง" คือหัวใจ**
> **2. recite mantra ก่อนเขียน — โดยเฉพาะ "หมกอะไรไว้ไหม?"**
> **3. เริ่ม session อ่าน log ล่าสุดก่อนเสมอ**

## หมายเหตุ
- **rigid:** 4 หัวข้อ + เพดาน 25 บรรทัด ห้ามตัด · **flexible:** ความยาว/ภาษาต่อหัวข้อ
- **ทำใน main เสมอ — ห้าม spawn agent มาเขียน log แทน** (บริบทงานอยู่ที่ main · spawn = แพงกว่า+รู้น้อยกว่า)
- ถ้าไม่มี `docs/log/` ให้สร้าง · repo ที่ไม่ใช่ git ก็เขียนได้ (มันคือความจำ ไม่ใช่ VCS)
- งานถาม-ตอบล้วน / แก้ typo / throwaway → ข้ามได้ (ไม่มีการตัดสินใจให้จำ)
